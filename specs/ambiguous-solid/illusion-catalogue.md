# 錯視立体カタログと製品の方向転換

## 方向転換

これまでのアプリは「任意の 2 シルエットを交差させる汎用ジェネレーター」だった。これを **既知の錯視立体を再現・体験・出力するサイト** に組み替える。自由な組み合わせ探索は残すが、**主役ではなく副次要素**とする。

理由：任意の図形ペアは「作れる」が「面白いとは限らない」。円 × 星は幾何学的には成立するが、これは錯視作品ではなく単なる交差立体である。錯視立体として名前が付いているものは、**なぜそう見えるかの機構が確立していて、驚きが再現可能**である点が違う。カタログを主役にすると、ユーザーは最初の 10 秒で「これは面白い」に到達できる。

## 12 の錯視立体と、この方式での実装可能性

CSG 交差方式（各シルエットを視線方向へ押し出し、共通部分を取る）で作れるかどうかで 3 つに分かれる。

### A. 現エンジンで今日作れる（2 軸・直交）

| # | 名称 | 必要なもの | 状態 |
|---|---|---|---|
| 12 | **影の両義立体** | 数字 `1` × 数字 `2` のシルエット | **テキスト入力で既に可能** |
| 2 | **トランプマークの変身立体** | ♠♥♦♣ のプリセット図形 | プリセット追加のみ |
| 3 | **左右反転矢印** | 矢印 × 矢印（非対称） | **矢印プリセットで既に可能** |

**#12 影の両義立体**の機構は、このアプリの数理そのものである。「X 方向の光で `1`、Y 方向の光で `2` の影」＝「X 方向の投影シルエットが `1`、Y 方向が `2`」であり、`M = M_1 ∩ M_2` がまさにその立体。**Visual Hull（視体積交差）** という名前が付いているが、実装は既存の交差そのもの。

**#3 左右反転矢印**は、原典（杉原）は「直角優先バイアス」を使う別機構だが、**両義立体として作り直せる**：シルエット A = 右向き矢印、シルエット B = 右向き矢印。正面からも側面からも右を指す立体になる。既存の非対称矢印プリセットで成立する。

### B. エンジン拡張が要る

| # | 名称 | 必要な拡張 |
|---|---|---|
| 4 | **三方向変身立体** | **3 軸目（視点 C）の交差** |
| 1 | **アンビギュアス・シリンダー** | **斜交軸（45°）** + 中空化 |

**#4 三方向変身立体**は `M = M_A ∩ M_B ∩ M_C`。既存の 2 軸交差の自然な一般化で、Manifold の `intersect` を 1 回増やすだけ。ただし**適格性の制約が急激に厳しくなる**。

> **訂正（実装で判明）**：当初この文書は「高さ `y` のスライスは `A_y × B_y × C_y` の三重直積」と書いていたが、**これは誤り**。C の押し出し軸を +Y に取ると C の断面は XZ 平面に乗るため、**`C_y` という量は存在しない**。正しくは
>
> ```
> slice(y) = (A_y × B_y) ∩ S_C
> ```
>
> で、`S_C` は**高さに依らない固定の 2D 領域**。C は「その高さの被覆」ではなく、横から一様に削る。
>
> 帰結：適格性は「3 つとも同じ高さに被覆を持つか」では判定できない。**A と B の被覆が、C の許す位置に重なっていなければならない。** カタログ項目の妥当性をこの誤った基準で確認すると、成立しない組み合わせを成立すると判断する。

3 つとも条件を満たす組み合わせは 2 軸のときよりはるかに少ない。プリフライトを 3 者版に拡張する必要がある。

**実測（プリセット 11 組）**：`円 × 正方形 × 三角形` は A・B が 1.000、C が 0.982（三角形の底辺両端が削れる）。完全一致するのは `円³`（Steinmetz 立体）、`正方形³`、`正方形 × 円 × 円`、`正方形² × 円` など、**3 面のうち 2 面以上が同じ形**の組。**「3 面とも異なり、かつ完全再現」は簡単には見つからない** — これは実装の限界ではなく三方向という条件そのものの性質で、原典が最適化計算で形を探しているのもそのためである。

**#1 アンビギュアス・シリンダー**（杉原厚吉）は 2 点で異なる：
1. **視線が斜め 45°**、かつ鏡像方向との組。直交ではない
2. **中空の筒**であり、中実の交差立体ではない。上端の輪郭が空間曲線で、そこから壁を下ろした形

中実の交差立体でも「正面が四角・側面が丸」は成立するが、原典の驚き（**筒の上端が波打っていて、鏡に映すと形が変わる**）は再現できない。段階的に扱う：
- **第 1 段階**：斜交軸に対応し、45° での中実交差を出す（FR-004 が既に規定済み）
- **第 2 段階**：交差立体の上端リング曲線を取り出し、壁を下ろして中空化する

第 2 段階は既存の CSG パイプラインの外側の処理になるため、**今回のスコープ外**とし、第 1 段階まで実装する。

### C. この方式では原理的に作れない（カタログに載せるが、生成しない）

| # | 名称 | 理由 |
|---|---|---|
| 5 | ペンローズの三角形 | 「特定視点で端点が重なる」錯視。投影シルエットの一致ではなく**遮蔽と接続の錯覚**。交差では作れない |
| 6 | ペンローズの階段 | 同上 |
| 7 | 宙に浮く屋根 / 突き抜ける柱 | 同上。オクルージョンの操作 |
| 8 | 何でも吸引するすべり台 | **重力方向の誤認**。シルエットではなく、脳の「柱は垂直・土台は水平」という前提を突く |
| 9 | 反重力スロープ | 同上。周囲のパースの歪みが本体 |
| 10 | ホロウマスク立体 | **凹凸の反転知覚**。運動視差の逆転であり、静的なシルエットの問題ではない |
| 11 | リバースパースペクティブ | 同上。消失点を幾何学的奥行きと逆に配置する |

**これらを「作れない」と明示することがカタログの価値になる。** 錯視立体という括りの中で、投影シルエット型（両義立体・Visual Hull）と、遮蔽型・重力型・視差型は**別の数理**であり、1 つのジェネレーターで全部は扱えない。この区別を示さないと、ユーザーは「ペンローズの三角形も作れるはず」と期待して失望する。

## 実装スコープ

### FR-100: 錯視立体カタログ
**Priority:** P0
THE SYSTEM SHALL 既知の錯視立体を、機構の説明とともに一覧として提示する
WHEN ユーザーがカタログの項目を選ぶ THE SYSTEM SHALL その錯視を再現する入力を設定し、生成する
THE SYSTEM SHALL 生成できない錯視（カテゴリ C）も掲載し、**なぜこの方式では作れないか**を説明する
**Rationale:** 任意ペアの探索は「作れる」が「面白いとは限らない」。名前と機構のある作品から入れば、最初の操作で驚きに到達する。作れないものを隠すと、期待と実体がずれる。

### FR-101: 第 3 の視点（三方向変身立体）
**Priority:** P1
WHEN 視点 C が有効 THE SYSTEM SHALL `M = M_A ∩ M_B ∩ M_C` を算出する
THE SYSTEM SHALL 3 者のプリフライト判定を行い、3 つとも被覆を持つ高さ帯のみが立体になることを提示する
**Rationale:** C は高さに依らない固定領域として横から削るため（上記の訂正を参照）、適格な組み合わせは 2 軸より大幅に狭い。事前に示さないと「何も出ない」が続く。

### FR-102: 斜交軸
**Priority:** P1
WHEN ユーザーが視点 B の軸角を変更する THE SYSTEM SHALL XZ 平面内の任意角で押し出し方向を再構成する（既定は直交 90°）
**Rationale:** アンビギュアス・シリンダーは 45° 系。FR-004 が既に規定していたが未実装だった。

### FR-103: 主従の入れ替え
**Priority:** P0
THE SYSTEM SHALL カタログを主たる入口として提示し、任意ペアの自由な組み合わせは副次的な手段として提供する
**Rationale:** 方向転換の本体。

## カタログ項目の定義

各項目が持つ情報：

```ts
interface IllusionEntry {
  id: string
  /** 表示名（日本語）と原名 */
  name: string
  originalName: string
  /** 分類 */
  category: 'ambiguous' | 'impossible' | 'gravity' | 'parallax'
  /** このアプリで生成できるか。false なら理由を示す */
  buildable: boolean
  /** 何が起きるか（現象） */
  phenomenon: string
  /** なぜそう見えるか（幾何学的機構） */
  mechanism: string
  /** buildable: false のときの、この方式で作れない理由 */
  notBuildableReason?: string
  /** buildable: true のときの再現設定 */
  preset?: {
    a: SilhouetteSource
    b: SilhouetteSource
    c?: SilhouetteSource
    /** 視点 B の軸角（度）。既定 90 = 直交 */
    axisAngleDeg?: number
  }
  /** 出典・考案者 */
  credit?: string
}
```

`buildable: false` の項目も同じ型で持ち、UI では「この方式では作れない理由」を主役に据えて見せる。
